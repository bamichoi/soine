# ADR-0008: 끼루 중개 테이블

- 날짜: 2026-11-25
- 상태: 제안 (일부를 ADR-0009가 대체)
- 작성자: 팀

> 결정 1(테이블의 `consultations`·`consultation_records`·`consultation_listings`·`meetings`·`meeting_records`),
> 4(삭제 금지 원칙의 예외), 5(상태), 6(계약 히스토리), 7(상담매물), 8(일정)은
> [ADR-0009: 끼루 상담을 미팅으로 합치기](./ADR-0009-끼루-상담을-미팅으로-합치기.md)가 대체한다.

## 배경 (Context)

끼루는 상가 임대 중개 백오피스다. 고객(임차인)이 연락하면 상담을 만들고, 매물을 두고 미팅을 하고,
계약까지 이어진다. 한 고객이 여러 상담을, 한 상담이 여러 매물로 미팅을, 한 미팅이 (취소 후 재계약으로) 여러 계약을 가질 수 있다.

## 결정 (Decision)

1. 테이블은 모두 `kkiru` 스키마에 둔다. 초이돌상 스키마와는 연결하지 않는다.

   | 테이블 | 내용 |
   | ------ | ---- |
   | `customers` | 고객(임차인). 고객 번호, 이름, 연락처(숫자만, 유일), 메모(선택) |
   | `listings` | 매물(임대만). 매물 번호, 이름, 주소, 면적(㎡), 층수, 임대료·보증금·권리금(만원), 주차, 화장실 수, 특징, 의뢰인, 상태(계약가능·미팅중·계약중·계약완료) |
   | `consultations` | 상담. 케이스 번호, 고객, 제목, 관심 상권, 희망 업종, 희망 평수 범위(평), 희망 층수, 희망 임대료·최대 보증금·최대 권리금(만원), 유입 경로(네이버부동산·인스타그램·기타+직접 입력), 상담일, 상태 |
   | `consultation_records` | 상담 내용 로그 |
   | `consultation_listings` | 상담매물 기록 (상담 ↔ 매물, 여러 개) |
   | `meetings` | 미팅. 상담, 대상 매물, 미팅 일시, 상태 |
   | `meeting_records` | 미팅 내용 로그. 종류: 내용·중단 사유·재개 사유·계약취소 사유 |
   | `contracts` | 계약. 미팅, 계약일, 임대인(이름·연락처), 실제 보증금·임대료·권리금, 임대차 기간, 특약, 계약금·수수료(만원), 내 매물·내 손님 여부, 상태, 취소 사유 |

2. 식별자는 UUID이고, 화면에는 8자리 무작위 번호(고객 번호, 케이스 번호, 매물 번호)를 쓴다.
   미팅·계약은 상담의 케이스 번호를 함께 쓰므로 주소에는 UUID를 쓴다.
3. 고객은 연락처로 같은 사람인지 찾는다. 연락처는 고칠 수 있고, 다른 고객과 겹치면 409.
4. **끼루 데이터는 삭제하지 않는다.** 로그 기록도 고칠 수만 있다. 모든 외래키는 `ON DELETE RESTRICT`.
5. 상태
   - 미팅: 미팅중 → (계약 생성) 계약중 → 계약완료 / 계약취소. 미팅중 ↔ 진행중단은 사유를 적어 바꾸고 미팅 로그에 남긴다.
   - 계약: 계약중 → 계약완료 / 계약취소(사유 필수, 미팅 로그에 남김). 계약취소된 미팅에서만 새 계약을 만들 수 있다.
   - 미팅 상태는 계약에 따라 바뀐다(최근 계약의 상태). 진행중단은 직접 바꾼다.
   - **상담 상태는 연결된 미팅 중 가장 앞선 단계로 자동으로 정한다.**
     계약완료 > 계약중 > 미팅중 > 계약취소 > 상담중. 진행중단된 미팅은 세지 않는다.
   - **매물 상태도 이 매물에 걸린 미팅 중 가장 앞선 단계로 자동으로 정한다**(2026-11-25 추가).
     계약완료 > 계약중 > 미팅중(미팅중·계약취소된 미팅) > 계약가능. 진행중단된 미팅은 세지 않는다.
     미팅·계약 상태를 바꾸는 트랜잭션 안에서 다시 계산한다(`syncListingStatus`).
   - 다른 고객이 미팅·계약 중인 매물도 상담매물·미팅 대상으로 고를 수 있다. 계약완료된 매물만 막는다.
   - 한 매물에 진행 중인 계약은 하나뿐이다. 계약을 만들 때 매물 행을 잠그고, 매물이 계약중이면 409.
   - 계약 상태 `contracting`의 화면 이름은 '계약예정'이다(상담·미팅·매물의 '계약중'과 구분).
   - 상태는 수정 폼에서 바꾸지 않고 버튼(미팅진행, 미팅중단·재개, 계약진행, 계약완료·취소)으로만 바꾼다.
6. 계약 히스토리는 따로 저장하지 않고 상담 로그와 미팅 로그를 날짜순으로 합쳐 보여 준다.
7. 상담매물 기록은 잘못 더한 매물을 빼기 위해 연결만 지울 수 있다(매물은 그대로 남는다).
8. 일정 API `GET /admin/kkiru/schedule?from&to`(최대 62일)는 미팅(미팅 일시)과 계약(계약일)을 돌려준다.
   진행중단 미팅과 취소된 계약은 빠진다.
9. 목록 API는 `field`(검색 항목, 기본 `all`), `q`, `status`(상태 필터), `sort`, `order`를 받는다.
   정렬을 고르지 않으면 각 목록의 날짜 최신순이다.
10. 예산(최대 보증금 + 최대 권리금)과 평↔㎡ 환산(1평 = 3.305785㎡)은 저장하지 않고 계산한다.

## 결과 (Consequences)

- 수입(계약완료 건의 수수료)은 이 테이블로 나중에 만든다.
- 매매 매물은 지금 다루지 않는다. 필요해지면 매물 형태와 매매가를 추가한다.
