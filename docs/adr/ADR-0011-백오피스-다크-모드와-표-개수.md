# ADR-0011: 백오피스 다크 모드와 표 한 페이지 개수

- 날짜: 2026-11-28
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

- 백오피스(`/login`, `/choidolsang/*`, `/goodplace/*`)는 라이트 화면만 있었다. 밤에 오래 쓰는 운영자가 어두운 화면을 원했다.
- 색은 이미 `globals.css` 토큰으로만 쓰고 있었지만, 채움 위 `text-white`, 직접 쓴 `rgba()` 그림자, `bg-black/40` 같은
  하드코딩이 남아 있어 토큰 값만 바꿔서는 다크가 되지 않았다.
- 목록 표는 백엔드 고정값(한 페이지 20건, `GOODPLACE_PAGE_SIZE`·`INQUIRY_PAGE_SIZE`·`RESERVATION_PAGE_SIZE`·`CONCEPT_PAGE_SIZE`)으로만 나왔다.
  한 번에 많이 보고 싶을 때 바꿀 수 없었다.
- 기준 명세: `docs/design/backoffice-theme.md`, 시안 `docs/design/backoffice-dark.html`, 가이드 `docs/design/goodplace-style-guide.md` 6·7절.

## 결정 (Decision)

### 화면 모드

1. 같은 토큰 이름에 다크 값만 둔다. 화면 코드에 `dark:` 클래스를 쓰지 않는다.
   - 라이트 `:root`, 다크 `:root[data-theme='dark']`, 시스템 다크 `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) }`.
   - 다크는 남색 기운 없는 중성 회색(바탕 #1d2025, 카드 #22252b)과 채도 낮은 하늘색 브랜드(#8eb2ea). 본문 대비 4.5:1 이상.
   - 새 토큰: `--on-accent`(채움 위 글자), `--backdrop`(모달·서랍 뒤 막), `--shadow-xs|sm|lift|pop|fill|fill-hover|danger-sm|danger-hover`.
     다크 그림자는 1px 밝은 테두리로 대신한다.
2. 고른 값은 브라우저 `localStorage['soine.theme']`(`light`|`dark`, 시스템이면 키 없음)에 두고 `<html data-theme>`로 건다.
   두 서비스와 로그인 화면이 같은 값을 쓴다. 서버에 저장하지 않는다.
3. 깜빡임 방지: `app/layout.tsx` `<head>`의 고정 문자열 인라인 스크립트가 첫 그림 전에 `data-theme`을 붙인다.
   `<html suppressHydrationWarning>`, `viewport`에 `colorScheme: 'light dark'`와 미디어별 `themeColor`.
   다른 탭은 `storage` 이벤트로 맞춘다.
4. 화면 모드 버튼: 데스크톱 헤더 오른쪽 `[화면 모드] 이름 [로그아웃]`, 모바일 서랍 아래 카드의 3칸 세그먼트, 로그인 화면 오른쪽 위.

### 표 한 페이지 개수 (API 계약 변경)

1. 목록 API가 쿼리 `size`를 받는다. 값은 `10`·`20`·`50`·`100` 중 하나, 없으면 `20`. 그 밖의 값은 `400`.
   - 대상: 굿플레이스 `GET /admin/goodplace/meetings`·`/contracts`·`/listings`·`/customers`(`PageQueryDto` 계열),
     초이돌상 `GET /admin/choidolsang/inquiries`·`/reservations`·`/concepts`.
   - 검증: `@IsOptional() @Type(() => Number) @IsIn([10, 20, 50, 100])`. 허용 값과 기본값은 `apps/backend/src/common/page-size.ts` 한 곳에 둔다.
2. 응답 `pagination.pageSize`에 실제 개수를 돌려준다(이전에는 항상 20). `totalPages`도 그 개수로 센다.
3. 페이지가 없는 응답(굿플레이스 수입의 계약 목록, 일정, 선택 목록 등)은 바뀌지 않는다.
4. 프론트는 주소 `?size=`에만 둔다(20이면 뺀다). 바꾸면 1페이지로 가고 다른 조건은 유지한다. 브라우저에 기억하지 않는다.
   상세로 넘기는 목록 쿼리에도 들어가 '목록으로'가 같은 개수로 돌아온다.
5. `packages/api-contract/openapi.yaml`에는 아직 목록 경로가 없어 이번에 고치지 않는다. 목록 경로를 계약에 올릴 때 `size`를 함께 적는다.

## 대안 (Alternatives)

1. Tailwind `dark:` 변형으로 화면마다 다크 색을 적는다.
2. 화면 모드를 쿠키에 저장하고 서버에서 `data-theme`을 그린다.
3. 개수를 자유 숫자(1~100)로 받는다.
4. 고른 개수를 `localStorage`에 기억한다.

## 대안 기각 이유

1. `dark:`는 모든 화면에 색을 두 번 적게 해 빠뜨리기 쉽다. 토큰 값만 바꾸면 한 곳에서 끝난다.
2. 루트 레이아웃에서 쿠키를 읽으면 모든 페이지가 요청마다 그려진다. 인라인 스크립트로 같은 효과를 정적으로 얻는다.
3. 자유 숫자는 화면 셀렉트와 맞지 않고, 캐시·테스트할 경우가 늘어난다. 네 값이면 충분하다.
4. 기억하면 다른 사람에게 링크를 보냈을 때 화면이 달라진다. 주소만으로 같은 화면이 나오게 한다.

## 영향 (Consequences)

### 장점

1. 운영자가 라이트·다크·시스템을 고를 수 있다. 기기 설정을 따르는 것이 기본이다.
2. 하드코딩 색이 사라져 이후 색 조정이 `globals.css` 한 곳에서 끝난다.
3. 목록을 한 번에 최대 100건까지 볼 수 있다.

### 단점/리스크

1. 다크 값이 `globals.css`에 두 번(선택 다크, 시스템 다크) 적힌다. 어긋나지 않게 주석으로 묶었다.
2. 인라인 스크립트는 엄격한 CSP(`'unsafe-inline'` 금지)를 쓰면 nonce가 필요하다. 지금 백오피스에는 CSP가 없다.
3. `size=100`이면 한 번에 읽는 행이 늘어난다(지금 데이터 규모에서는 문제 없음).
4. 이전 클라이언트가 `pageSize`를 늘 20으로 가정했다면 영향이 있다. 백오피스 외 소비자는 없다.

## 비용 (Cost)

### 산정 기준

1. 추가 인프라나 구독 없음. 개발·검토 시간만 든다.

### 예상 비용

1. 월 고정비: 0
2. 월 변동비: 0
3. 월 합계(예상): 0

### 민감도/변동 조건

1. 해당 없음.

## 완화 전략

1. 허용 값을 백엔드 한 파일(`common/page-size.ts`)과 프론트 한 파일(`lib/list-query.ts`)에 두고, 백엔드 spec으로 모든 목록 DTO의 허용·거절을 확인한다.
2. 하드코딩 색은 `grep`으로 0줄을 확인한다(주석·`globals.css`, 브라우저 바 색 `themeColor` 제외).

## 적용 범위 (Scope)

- `apps/backoffice` 전체(로그인, 초이돌상, 굿플레이스).
- `apps/backend`의 초이돌상·굿플레이스 목록 API.

## 롤백/재검토 조건

1. 다크 화면에서 읽기 어렵다는 피드백이 반복되면 토큰 값을 다시 잡는다.
2. CSP를 도입하면 인라인 스크립트에 nonce를 붙인다.
3. 100건으로 느려지는 목록이 생기면 최대값을 줄이거나 그 목록만 제한한다.
