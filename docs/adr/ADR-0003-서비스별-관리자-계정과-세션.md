# ADR-0003: 서비스별 관리자 계정과 세션

- 날짜: 2026-11-23
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

백오피스 하나(`admin.choidolsang.com`)에서 초이돌상과 끼루를 운영한다.
두 서비스는 운영 주체와 데이터가 다르므로 계정과 데이터를 섞지 않아야 한다.

## 결정 (Decision)

1. **DB 분리:** 서비스마다 PostgreSQL 스키마를 둔다.
   - `choidolsang` 스키마: 초이돌상 테이블
   - `kkiru` 스키마: 끼루 테이블
   - Prisma `multiSchema`의 `@@schema`로 지정하고, 두 스키마 사이에 관계를 두지 않는다.
2. **계정 분리:** 관리자 계정은 `<service>.admins`에 서비스별로 저장한다.
   같은 이메일이 두 서비스에 각각 존재할 수 있으며, 서로 다른 계정이다.
3. **세션 분리:** 서버 세션(`express-session` + `connect-pg-simple`)을 서비스별로 둔다.
   - 세션 테이블: `<service>.admin_sessions`
   - 쿠키: `soine.<service>.admin.sid` (`httpOnly`, `sameSite=lax`, 운영에서 `secure`, 30일. 처음에는 12시간이었으나 매일 다시 로그인해야 해서 늘렸다)
   - 같은 브라우저에서 두 서비스에 각각 로그인할 수 있다.
4. **API:** 서비스는 경로로 구분한다. 경로마다 해당 서비스의 세션 미들웨어가 붙는다.
   - `POST /admin/:service/auth/login` — `{ email, password }` → `{ id, email, name, service }`
   - `GET /admin/:service/auth/me` — 로그인한 관리자 정보, 없으면 401
   - `POST /admin/:service/auth/logout` — 204
   - 백오피스는 `/api/admin/*`를 rewrite로 백엔드 `/admin/*`에 넘긴다.
5. **비밀번호:** argon2id로 해시한다. 계정 생성은 `pnpm --filter @soine/backend admin:create`.
6. **무차별 대입 방지:** 비밀번호를 5회 틀리면 15분 동안 잠근다(429).
   없는 이메일도 해시 검증을 수행해 응답 시간으로 계정 존재 여부가 드러나지 않게 한다.
7. **세션 고정 방지:** 로그인 성공 시 세션 ID를 새로 발급한다.
8. 로그인 화면은 탭으로 서비스를 고른 뒤 그 서비스 계정으로 로그인한다.

## 대안 (Alternatives)

1. 공용 관리자 테이블 하나에 서비스 소속 목록을 두고, 한 계정으로 여러 서비스에 접근
2. 서비스별 별도 데이터베이스
3. JWT 기반 무상태 인증

## 대안 기각 이유

1. 두 서비스의 계정이 섞이고, 한 서비스의 권한 오류가 다른 서비스 데이터 노출로 이어질 수 있다.
2. 현재 규모에서 DB 인스턴스와 마이그레이션 관리 비용이 크다. 스키마 분리로 충분하다.
3. 즉시 로그아웃·계정 정지 반영이 어렵다. JunSem과 같은 서버 세션 방식을 유지한다.

## 영향 (Consequences)

### 장점

1. 서비스 간 계정·데이터 경계가 DB 수준에서 명확하다.
2. 나중에 한 서비스를 별도 DB로 옮기기 쉽다.

### 단점/리스크

1. 두 서비스를 모두 운영하는 사람은 계정 두 개를 관리해야 한다.
2. 인증 코드가 서비스별 Prisma 모델을 분기 처리해야 한다.
3. `_prisma_migrations` 테이블은 `public` 스키마에 남는다.

## 롤백/재검토 조건

1. 두 서비스를 함께 운영하는 관리자가 많아져 계정 통합 요구가 커질 때
2. 관리자 역할(권한 등급)이 필요해질 때
