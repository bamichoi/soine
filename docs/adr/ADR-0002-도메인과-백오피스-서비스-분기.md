# ADR-0002: 도메인과 백오피스 서비스 분기

- 날짜: 2026-11-23
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

초이돌상은 고객 서비스와 백오피스가 필요하고, 끼루는 백오피스만 필요하다.
도메인은 `choidolsang.com` 하나만 구매한다.

## 결정 (Decision)

1. 도메인을 다음과 같이 나눈다.
   - `choidolsang.com` → `apps/choidolsang-web` (고객용)
   - `admin.choidolsang.com` → `apps/backoffice` (초이돌상·끼루 운영자 공용)
   - `api.choidolsang.com` → `apps/backend`
2. 백오피스는 하나의 Next.js 앱으로 만들고, 서비스는 경로로 분기한다.
   - `/login`: 로그인 화면. 탭으로 초이돌상/끼루를 고른 뒤 그 서비스 계정으로 로그인한다.
   - `/choidolsang/*`: 초이돌상 백오피스
   - `/kkiru/*`: 끼루 백오피스
3. 관리자 계정은 서비스마다 따로 있다. 한 계정으로 두 서비스에 로그인하지 않는다.
   계정·세션 상세는 ADR-0003을 따른다.
4. 서비스별 접근 권한은 백엔드에서 강제한다. 프론트 경로 가드는 UX 목적이다.
5. 고객 인증과 관리자 인증은 세션과 비밀키를 분리한다.

## 대안 (Alternatives)

1. 서비스별 서브도메인(`choidolsang.soine.com`, `kkiru.soine.com`)과 별도 포털 도메인
2. 초이돌상 백오피스와 끼루 백오피스를 별도 Next.js 앱으로 분리

## 대안 기각 이유

1. 도메인을 추가로 구매해야 하고, 서브도메인 간 쿠키 공유와 Host 기반 라우팅이 필요하다.
2. 로그인, 세션, 레이아웃이 중복되고 배포 단위가 늘어난다.

## 영향 (Consequences)

### 장점

1. 도메인 하나로 운영할 수 있다.
2. 로그인 화면과 레이아웃을 한 앱에서 관리한다.

### 단점/리스크

1. 끼루 백오피스 주소에 `choidolsang`이 포함된다. 내부 운영 도구라 허용한다.
2. 한 앱 안에서 두 서비스 코드가 섞이지 않도록 경로별 폴더 경계를 지켜야 한다.

## 롤백/재검토 조건

1. 끼루가 별도 고객 서비스와 도메인을 갖게 될 때
