# ADR-0007: 초이돌상 매출 집계

- 날짜: 2026-11-24
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

백오피스 "매출" 메뉴에서 기간별 매출과 추이, 돌상 컨셉별 매출, 매출 내역을 본다.
예약을 업무 완료하면 매출에 반영된다(ADR-0006).

## 결정 (Decision)

1. 매출 테이블을 따로 만들지 않고 `choidolsang.reservations`에서 바로 집계한다.
   - 매출 = `status = completed`인 예약의 `totalAmount`
   - **기준일은 업무 완료를 누른 시각(`completedAt`)의 한국 날짜**다.
   - 취소환불 예약은 규정이 정해질 때까지 매출에 넣지 않는다(예약금 처리 보류).
   - 예정 매출 = 그 기간에 행사(`eventAt`)가 있는 예약중 예약의 합계. 매출과 따로 보여 준다.
2. 기간은 한 달(`month=YYYY-MM`) 또는 한 해(`year=YYYY`)이며 한국 시간 자정 기준 [시작, 끝)이다.
3. API (모두 초이돌상 관리자 세션 필수)
   - `GET /admin/choidolsang/sales/summary?month=` 또는 `?year=` —
     합계·건수·건당 평균, 앞 기간(지난달·지난해) 대비 증감률, 예정 매출,
     12개 달 추이(월: 최근 12개월, 연: 그해 1~12월), 컨셉별 매출(건수·합계·비중, 많은 순)
   - `GET /admin/choidolsang/sales/items?month=|year=&page=` — 매출 내역 20건씩, 완료 시각 최근 순
4. 화면: 기간 선택(월별·연간, 이전·이번 달·다음), 요약 4칸, 월별 매출 막대그래프(막대를 누르면 그 달로),
   컨셉별 매출 표, 매출 내역 표. 엑셀 다운로드는 보류.

## 대안 (Alternatives)

1. 업무 완료 시 매출 테이블에 행을 복사 — 예약을 고치면 두 곳이 어긋날 수 있어 지금은 하지 않는다.
2. 행사일 기준 집계 — 완료 처리 시점과 매출 시점을 맞추기 위해 완료 시각 기준으로 정했다.

## 결과 (Consequences)

- 완료한 예약의 금액은 수정할 수 없으므로(ADR-0006) 지난 매출이 바뀌지 않는다.
- 집계는 기간의 행을 읽어 서버에서 묶는다. 건수가 많아지면 DB 집계(`date_trunc`)로 바꾼다.

## 롤백/재검토 조건

1. 취소환불 예약금 규정이 정해질 때
2. 추가 결제·부분 환불·할인처럼 예약 금액과 실제 받은 돈이 달라질 때 (결제 내역 테이블 검토)
3. 엑셀 다운로드가 필요해질 때
