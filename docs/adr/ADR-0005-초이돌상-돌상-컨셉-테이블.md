# ADR-0005: 초이돌상 돌상 컨셉 테이블

- 날짜: 2026-11-23
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

초이돌상은 돌상 세트를 상품으로 판다. 백오피스 "돌상 컨셉" 메뉴에서 상품(이름, 구성품, 가격)을 관리해야 한다.
나중에 문의의 희망 돌상 컨셉과 예약이 이 상품을 참조할 수 있다.

## 결정 (Decision)

1. `choidolsang.concepts` 테이블을 만든다.

   | 컬럼                     | 타입         | 필수 | 설명 |
   | ------------------------ | ------------ | ---- | ---- |
   | `id`                     | UUID         | ✓    | 식별자. 화면 주소에도 쓴다 |
   | `name`                   | VARCHAR(100) | ✓    | 컨셉 이름 |
   | `components`             | TEXT[]       | ✓    | 구성품 목록. 기본값 빈 목록, 추가한 순서대로 저장 |
   | `price`                  | INTEGER      | ✓    | 가격 (원, 0 ~ 100,000,000) |
   | `deletedAt`              | TIMESTAMPTZ  |      | 숨김 삭제 시각 |
   | `createdAt`, `updatedAt` | TIMESTAMPTZ  | ✓    | |

2. 구성품은 화면에서 하나씩 입력해 +로 더하는 목록이다. 항목은 최대 50개, 하나에 최대 200자이고,
   앞뒤 공백을 지운 뒤 빈 항목은 뺀다. 처음에는 자유 글(TEXT)이었으나 목록으로 바꿨다
   (마이그레이션 `change_choidolsang_concept_components_to_list`, 기존 글은 줄 단위로 나눠 옮김).
3. 삭제는 숨김 삭제다. 문의·예약이 컨셉을 참조하게 되면 기록이 깨지지 않아야 하기 때문이다.
4. API (모두 초이돌상 관리자 세션 필수)
   - `GET /admin/choidolsang/concepts?page=&q=&field=&sort=&order=` — 목록 20개씩, 기본은 최근 등록 순
     - `field`: `all`(기본) | `name` | `components`. 구성품은 배열이라 SQL(`array_to_string ... ILIKE`)로 찾는다.
     - `sort`: `createdAt`(기본) | `name` | `price`, `order`: `asc` | `desc`
   - `GET /admin/choidolsang/concepts/options` — 고를 수 있는 컨셉 전체 `[{ id, name, price }]`, 이름순
   - `GET /admin/choidolsang/concepts/:id` — 상세, 없거나 삭제됐으면 404
   - `POST /admin/choidolsang/concepts` — 추가 `{ name, components, price }`
   - `PATCH /admin/choidolsang/concepts/:id` — 수정, 모든 항목을 다시 보낸다
   - `DELETE /admin/choidolsang/concepts/:id` — 숨김 삭제(204)

## 대안 (Alternatives)

1. 구성품을 별도 테이블(`concept_components`)로 분리 — 구성품마다 수량·가격이 생기면 검토한다.
2. 가격을 DECIMAL로 저장 — 원 단위 정수로 충분하다.

## 결과 (Consequences)

- 문의의 희망 돌상 컨셉은 이 테이블을 참조한다 (`inquiries.desiredConceptId`, ADR-0004).
