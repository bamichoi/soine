# ADR-0004: 초이돌상 문의 테이블

- 날짜: 2026-11-23
- 상태: 제안
- 작성자: 팀

## 배경 (Context)

초이돌상 백오피스에서 고객 문의를 모아 보고, 예약 확정 여부를 관리해야 한다.
기존 메뉴 "상담"은 "문의"로 이름을 바꾼다.

## 결정 (Decision)

1. `choidolsang.inquiries` 테이블을 만든다.

   | 컬럼                   | 타입                 | 필수 | 설명                |
   | ---------------------- | -------------------- | ---- | ------------------- |
   | `id`                   | UUID                 | ✓    | 내부 식별자         |
   | `code`                 | VARCHAR(16), UNIQUE  | ✓    | 문의 번호. 8자리 무작위 코드 (예: `7K3FQ9AM`) |
   | `inquiredOn`           | DATE                 | ✓    | 문의 날짜           |
   | `content`              | TEXT                 | ✓    | 문의 내용           |
   | `desiredReservationAt` | TIMESTAMPTZ          |      | 희망 예약 날짜·시간 |
   | `location`             | VARCHAR(200)         |      | 장소                |
   | `desiredConcept`       | VARCHAR(200)         |      | 희망 돌상 컨셉      |
   | `status`               | `inquiry_status`     | ✓    | 상태, 기본값 `pending` |
   | `rejectionReason`      | TEXT                 |      | 거절 사유. 거절 상태일 때만 값이 있음 |
   | `createdAt`, `updatedAt` | TIMESTAMPTZ        | ✓    |                     |

2. 상태는 `choidolsang.inquiry_status` enum으로 둔다: `pending`(대기), `confirmed`(예약확정), `rejected`(거절).
3. 희망 예약 일시는 시각대를 포함해 저장하고, 백오피스에서는 한국 시간(Asia/Seoul)으로 표시한다.
4. 희망 돌상 컨셉은 우선 자유 입력 문자열로 둔다. 돌상 컨셉 테이블이 생기면 참조로 바꾼다.
5. 화면과 URL에서는 UUID 대신 문의 번호(`code`)를 쓴다. 문의 건수나 순서가 드러나지 않도록
   헷갈리는 글자(I, L, O, U)를 뺀 Crockford Base32 8자리 무작위 코드로 만들고, 겹치면 다시 생성한다.
   순서가 없는 값이므로 정렬 대상에서 뺀다.
6. API (모두 초이돌상 관리자 세션 필수)
   - `GET /admin/choidolsang/inquiries` — 목록, 20건씩
     - `page`: 페이지 (기본 1)
     - `field`: 검색 항목 `all`(기본) | `code` | `content` | `location` | `desiredConcept` | `status`
     - `q`: 검색어 (최대 100자). 글자 항목은 부분 일치(대소문자 무시), 문의 번호는 부분 일치(대소문자 무시),
       상태는 표시 이름(대기·예약확정·거절)의 일부로 찾는다.
     - `sort`: `inquiredOn`(기본) | `desiredReservationAt` | `location` | `desiredConcept` | `status`
     - `order`: `asc` | `desc`(기본). 빈 값은 맨 뒤, 같은 값은 최근 등록 순.
   - `GET /admin/choidolsang/inquiries/:code` — 상세 (대소문자 무시), 없으면 404
   - `POST /admin/choidolsang/inquiries` — 추가
     - 필수: `inquiredOn`(YYYY-MM-DD), `content`(최대 5000자)
     - 선택: `desiredReservationAt`(시간대 포함 ISO 8601), `location`, `desiredConcept`(각 최대 200자),
       `status`(기본 `pending`), `rejectionReason`(상태가 `rejected`이면 필수, 최대 1000자, 그 외엔 무시).
       빈 문자열은 null로 저장.

   ```json
   {
     "items": [{ "id": "…", "code": "7K3FQ9AM", "inquiredOn": "2026-11-20", "content": "…",
                 "desiredReservationAt": "2026-12-05T02:00:00.000Z",
                 "location": "…", "desiredConcept": "…", "status": "pending" }],
     "pagination": { "page": 1, "pageSize": 20, "total": 45, "totalPages": 3 }
   }
   ```

   - `POST /admin/choidolsang/inquiries/:code/reject` — `{ reason }`(필수, 최대 1000자). 대기 → 거절.
   - `POST /admin/choidolsang/inquiries/:code/reopen` — 거절 → 대기, 거절 사유는 지운다.
   - 상태 전환은 현재 상태를 조건으로 갱신해 동시에 눌러도 한 번만 반영된다. 허용되지 않은 전환은 409.
   - 예약확정(`confirmed`) 전환은 예약 폼(예약 진행)에서 처리할 예정이다.
7. 관리자 API는 `AdminSessionGuard` + `@RequireAdminService('<service>')`로 보호한다.
   세션 미들웨어가 `admin/<service>/*` 경로별로 붙으므로 컨트롤러 경로와 서비스가 같아야 한다.

## 대안 (Alternatives)

1. 희망 날짜와 시간을 별도 컬럼으로 분리
2. 희망 돌상 컨셉을 처음부터 컨셉 테이블 참조로 설계

## 대안 기각 이유

1. 날짜만 알고 시간은 모르는 문의가 생기면 그때 분리를 검토한다. 지금은 하나의 일시로 충분하다.
2. 돌상 컨셉 데이터 구조가 아직 정해지지 않았다.

## 영향 (Consequences)

### 장점

1. 문의 목록을 백오피스에서 바로 조회할 수 있다.

### 단점/리스크

1. 문의 내용 수정·삭제, 예약 진행(예약확정 전환)은 아직 없다.
2. 희망 돌상 컨셉이 자유 입력이라 표기가 제각각일 수 있다.

## 롤백/재검토 조건

1. 돌상 컨셉 테이블이 생길 때 (`desiredConcept` 참조 전환)
2. 문의가 예약으로 전환되는 흐름을 설계할 때
